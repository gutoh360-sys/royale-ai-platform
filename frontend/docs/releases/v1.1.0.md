# Release v1.1.0 — Authentication & Authorization Platform

**Data:** 2026-07-30

**Responsável:** Principal Software Architect

## Resumo

Esta release inaugura a segunda fase da plataforma com um sistema completo de Authentication & Authorization. Toda a Executive Insight Platform (v1.0.0) permanece inalterada.

## O que foi construído

### Autenticação
- Login com validação de credenciais
- Sessão via cookie com HMAC-SHA256
- Logout com destruição de sessão
- Middleware de proteção de rotas
- 6 papéis (Roles) pré-definidos
- 22 permissões (Permissions) centralizadas

### Usuário Inicial
- Login: `adm`
- Senha: `123` (armazenada com hash scrypt + salt)
- Papel: ADMIN (acesso total)

### Páginas
- `/login` — Tela de login profissional
- `/access-denied` — Página 403
- Todas as rotas protegidas (exceto /login e /access-denied)

### Menu Dinâmico
- Itens do menu são filtrados automaticamente conforme permissões do usuário
- Usuário VIEWER vê apenas Dashboard, Marketplace, Estoque, etc. (sem edição)
- Usuário FINANCE vê apenas Financeiro e Relatórios

## Arquitetura

```
src/auth/
├── domain/
│   ├── types.ts           — User, Role, Session, AuthUser
│   ├── permissions.ts     — Permission Registry (22 permissões)
│   └── role-permissions.ts — 6 papéis → permissões
├── application/
│   ├── auth-service.ts    — Authenticate, ValidateSession
│   ├── permission-service.ts — hasPermission, requirePermission
│   └── nav-filter.ts      — Filtro de navegação
├── infrastructure/
│   ├── password.ts        — scrypt + salt (Node.js crypto)
│   ├── users.ts           — Repositório local de usuários
│   └── session.ts         — Cookie HMAC-SHA256 (Web Crypto API)
├── session/
│   └── auth-provider.tsx  — React Context + Provider
├── components/
│   ├── login-form.tsx     — Formulário de login
│   └── access-denied.tsx  — Página 403
└── guards/
    ├── require-auth.tsx    — Route guard
    └── require-permission.tsx — Permission guard

src/app/api/auth/
├── login/route.ts
├── logout/route.ts
└── me/route.ts

src/middleware.ts           — Edge Middleware
```

## Preparação Futura

| Componente Atual | Substituição Futura |
|-----------------|---------------------|
| `users.ts` (local) | Banco de dados |
| `session.ts` (HMAC) | JWT |
| `login` (local) | Azure AD / Google / LDAP / OAuth |
| `password.ts` (scrypt) | Identity Provider externo |

Apenas a camada `infrastructure/` precisa ser alterada — o domínio e application permanecem intactos.
